# Sensitive tables matrix — new entries

This addendum extends `sensitive-tables-matrix.md` without rewriting its legacy
classifications. The database unit test checks the union of both files against
the exported schema. New entries follow the same classification taxonomy.

| `table_name` | schema | classification | readers | writers | encryption_needed_at_rest | notes |
| --- | --- | --- | --- | --- | --- | --- |
| `group_moderation_scopes` | nautilo | OPERATOR-INTERNAL | Trusted moderation authorization adapter | Authorized Group administration through the product role | no (Group and Room IDs only) | Binds a Group's moderation capability to explicit Rooms; membership alone does not grant moderation. Product-only RLS and privileges. |
| `moderation_subjects` | nautilo | OPERATOR-INTERNAL | Trusted moderation and enrollment admission adapters | Canonical moderation transaction | yes (identity-linking metadata) | Retained identity digest can match a banned identity after local account deletion. No raw issuer or external subject is stored here. Not exposed through the member directory. |
| `moderation_actions` | nautilo | OPERATOR-INTERNAL | Authorized moderation history and trusted delivery recovery | Canonical moderation transaction; narrow audit, convergence, cleanup checkpoints and text erasure | yes (reason and private note may contain personal information) | Durable idempotent action receipt; requester and subject identifiers, request digest and private moderation text. Product-only RLS; private notes never enter Room broadcasts or personal-feed payloads. |
| `moderation_restrictions` | nautilo | OPERATOR-INTERNAL | Trusted current-access and moderation adapters | Canonical moderation apply/lift transactions | no (restriction metadata only) | Current restriction scope, lifetime and revision with create/lift operation references. Independent restrictions compose; historical action receipts do not authorize access. Product-only RLS. |
| `server_admission` | nautilo | OPERATOR-INTERNAL | Trusted authentication, enrollment and work admission adapters | Canonical moderation withdrawal and approved enrollment transactions | no (Human ID and admission state only) | Admission epoch invalidates stale work while preserving the account and membership graph. Lifting a restriction does not automatically readmit a Human. Product-only RLS. |
| `server_moderation_policy` | nautilo | OPERATOR-INTERNAL | Trusted moderation policy and invite enrollment adapters | Authorized Server moderation administration | no (policy switches and updater ID only) | Singleton moderation enablement, join pause, required approval and revision. Product-only RLS; new installations default to disabled. |
| `message_deletion_receipts` | nautilo | OPERATOR-INTERNAL | Authorized `view_audit_log` lookup in `packages/server/src/lib/message-deletion-receipts.ts`; content-report retry recovery | Canonical hard-delete transaction in `packages/server/src/messaging/message-deletion.ts` | no (content-free metadata only) | Deletion facts with Room/message and actor identifiers, bounded source/authority/outcome codes, optional report ID, and commit time. No message body or preview. Receipts survive the deleted message; the security route restricts non-owner lookups to the caller's actor. |
| `personal_provider_credentials` | nautilo | CREDENTIAL | Trusted server provider-custody adapters only | Trusted server credential lifecycle through owner-scoped helpers | yes (authenticated ciphertext) | One current encrypted credential per Human/provider. The product role alone may access envelope fields; `nautilo_agent`, `nautilo_crypto`, and `PUBLIC` are denied. Plaintext and historical envelopes are prohibited. |
| `soul_generation_attempts` | nautilo | OPERATOR-INTERNAL | Trusted server Soul setup admission only | The same admission reserves an attempt before provider work and prunes expired receipts | no (Human ID and timestamp only) | Rolling per-Human server-funded setup limit. Failed attempts count; no prompt, Soul text, provider credential, or token usage is stored. The Human row lock serializes reservations across server processes. |
| `server_public_join` | nautilo | OPERATOR-INTERNAL | Public join routing and authorized Server administration | Authorized Server administration and one-time legacy shortcut import | no (Invite and updater IDs only) | Singleton selection of an ordinary revocable Invite for `/join`, with a revision to prevent stale admin updates. The selected Invite is rechecked at each visit. |
