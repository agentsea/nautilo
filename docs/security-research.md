# Security research completion and recovery

A security investigation runs inside an ordinary, durable Task with `file` and
`security_scan`. The Task owns its checkpoint, cancellation, model and report.
Desktop owns the authorized source root and evidence ledger. A successful
scanner run supplies leads; it does not establish source-review coverage.

## Model selection

Security Tasks use the Agent's configured default model under the same eligibility
and operator routing checks as other Native Tasks. An exact Task model pin remains
strict; explicit privacy, intelligence or cost profiles keep their existing
meaning. Security tooling does not silently replace the configured model with a
catalog-preferred provider. Existing catalog preference metadata remains readable
for compatibility and is not an audit-quality certificate.

Selection, execution and provider construction share the existing operator
`NAUTILO_ALLOW_CHINA_UPSTREAM` opt-in. An explicit denial overrides that setting;
an injected environment is authoritative. This does not bypass credentials,
signed catalog enablement or capability checks.

This preserves the configured choice rather than claiming one model is best for
all repositories. Qualification records the actual resolved model and evaluates
its source reasoning and final report; neither catalog intelligence tiers nor a
single successful fixture establish comprehensive audit quality.

## Completing the requested scope

The restricted research Task receives its investigation workflow in the leading
system prompt. It plans concrete behavior units, records source-backed conclusions
and notes
while tracing them, checks claimed guards at their actual callers, and verifies
absence claims across relevant producers and consumers. The model chooses depth,
grouping and sampling from risk and evidence, documenting those scope decisions.
Completed work is revisited only for a specific gap, contradiction or source change.
Tool descriptions retain operation
and evidence contracts. This guidance is not a guarantee of model quality.

The model records repository sections and trust boundaries before narrowing
its investigation. A repository-map label is a plan, never completion proof.
Completed, source-backed review units derive their section coverage when no
explicit coverage record exists. Existing explicit coverage retains precedence;
derivation does not persist another model-authored record or certify reasoning.
Desktop independently inventories the authorized target, including file versions,
explicit exclusions and unavailable entries. Inventory entries are accounted for
through behavior assignments or explicit
exclusions. Assignment is planning, not proof of review: completed units retain
their trace, conclusions, uncertainties and relevant current assigned-source
references. Related support files may share a unit; completion does not require
a citation from every assigned file. A `not_applicable` unit needs an explicit
scope rationale, without a fabricated source citation.

Hypothesis and counterevidence records are available when they clarify an
investigation; they are not mandatory paperwork for every unit. Explicit linked
hypotheses and open questions must be resolved. Every scanner observation needs
an exact supported disposition, including each member of a grouped finding.
Scanner silence and family counts do not establish source-review coverage.
Risk-based sampling is allowed when its rationale and limitations are recorded.
Changed source invalidates qualifying evidence and reopens affected work while retaining
the old notes for comparison.

`results` with `finalize:false` keeps research open. Premature finalization
returns `research_incomplete`, with a short error label and a separate
`error.continuation` instruction. The ledger stays active and its records and
source evidence remain available. The model continues inside the same Task,
scan and Desktop authorization. It does not need the Human to schedule each
remaining section again.

Accepted record and status receipts expose `researchProgress.nextResearchWork`,
derived from the existing complete ledger checks. It identifies the next
section, unit, hypothesis or scanner-disposition obligation before a finalization
attempt. A completed unit count can coexist with an unmatched mapped section.
Null does not certify source freshness, exhausted file discovery, report export
or correct reasoning; older receipts can omit this field.

Hypothesis evidence failures name the exact ledger record, current revision
and missing reference fields. A section can link multiple hypotheses; fixing
another linked record does not satisfy the failed prerequisite. Re-read the
named record when its revision changes, inspect the missing evidence, and
update that record before trying finalization again.

A concrete external/source blocker can support `limited` coverage. The
blocker must affect the requested scope. An external implementation merely
mentioned in repository documentation is an assumption, not additional work
silently added to that scope. A source-backed `not_applicable` decision can
exclude it while retaining the inspected in-repository trust boundary. Absent
code must not be described as denied access unless a read was actually denied.
Unavailable scanner coverage is also distinct from unread repository code;
both can affect the combined ledger status and must be explained separately.
The coverage record names `blocker` and links the investigated hypothesis and any
unanswered question. Answered open questions receive an evidence-backed
`resolution` update. The latest checkpoint identifies work still open;
resolved hypotheses referenced by an earlier checkpoint do not remain open.

An ordinary prose ending without a qualifying sealed ledger returns to
the model with continuation guidance. Repeated attempts to end without
progress use the existing no-progress correction and termination policy.
Genuine cancellation, revoked access and provider failures retain their actual
outcomes. Explicit Human-reply waits and approval boundaries remain intact.

A native Task failure or cancellation wakes the parent with a lifecycle
receipt and an exact Task inspection selector. Before explaining attempted
work, coverage or failure cause, the parent must inspect saved evidence through
the ordinary authorized Task tool. Unavailable inspection means unverified
work, not absent work. Local execution continuation is separate from permission
to read durable history; inspection does not authorize restarting the Task.

Successful finalization closes the scan to mutations. New sealed all-results
receipts carry an export snapshot digest and item count. For workspace research,
the runtime retrieves the exact accepted report draft from canonical history,
without requiring another model response to reproduce it. Legacy research keeps
its final narrative. The runtime reads the entire immutable export through the
same authorized Desktop continuation without putting those pages into model
history. It verifies the snapshot, each item and cursor, complete item count
and content digest before creating the artifact. Older receipts without this
snapshot retain their complete canonical-pagination path. The Task runtime
persists the report with the accepted research log and source, observation and
inventory indexes as a Workspace artifact. The appendix is independent of the
model's prose and includes
the exact final status and every scanner lane's coverage and error. Missing or
incomplete export cannot become successful report delivery. `partial`, probe
failures and actual coverage gaps remain visible; a completed Task or fully
retrieved ledger is not a security certification.

Failed report delivery pauses the Task with its completed investigation saved.
Resume retries export on the same TaskRun without calling the model. Ordinary
paused native research also resumes its original TaskRun and model. After a
server restart, the runtime revalidates the saved owner, Desktop session,
pairing, folder, workspace and current capabilities before refreshing the
transport binding. It preserves the original grant expiry and graph's pending
work and approvals. An unavailable Desktop keeps the Task paused and the saved
grant intact for reconnect; changed authority cannot be silently substituted.
Pause and Stop are checked again when the queued Job starts and at the final
completion transaction.

The completion checks establish structured evidence closure against the inventory
and mapped plan. They cannot certify that the model discovered every relevant behavior,
inspected every line, or reasoned correctly. Assess the report's exact reviewed
paths and traces. A small-fixture qualification is not an exhaustive audit of
a larger repository.

## Sustained work and recoverable context

Fresh audit Tasks use a coordinator workspace with optional investigator workspaces
and a focused final report reviewer inside the existing protected graph. The TaskRun, selected model,
Desktop authority and cancellation signal remain the same. A standalone local
`security_scan` handoff validates accepted ledger references and a current
checkpoint, then returns a canonical control receipt. The next prepared model
context starts at that complete handoff cycle; the full archive is unchanged.
Legacy checkpoints without this workflow flag retain their previous path.
Explicit `scanners_only` work does not acquire a model-led review requirement.

The coordinator may investigate directly or assign a focused behavior while
retaining the outstanding plan. Investigators save source-backed results in
existing review units and linked notes, then return directly to the coordinator.
Per-unit reviewer handoffs are optional for specific concerns. Closed unchanged
units remain settled; reassignment requires an explicit reopening of the affected
unit and the reason. Optional review acceptance binds the result revision and
transitive evidence. The coordinator's saved plan is retained when a worker
returns. Runtime prerequisites verify structure and revision identity, never the
semantic quality of the conclusion.

Each outgoing workspace saves a substantive checkpoint after its source work.
The role seed contains IDs and execution controls; untrusted research prose is
loaded through ordinary protected tools. The coordinator sends the complete
draft in ordinary protected handoff input for report review while the ledger is
still writable. Investigators and reviewers cannot seal or end the Task. The
coordinator requests one focused review of the actual report draft before
sealing. The reviewer reuses saved evidence and reopens source for a specific
unsupported, contradictory or changed claim. Material conclusion or supporting
evidence changes invalidate acceptance; unrelated notes and checkpoints do not.
Explicit unresolved reviewer follow-ups still prevent sealing. There are no
concurrent writes into the replacing message-state reducer, child Task joins,
new scheduler or alternate provider path.

Archival preservation does not require replaying every earlier role's source
into each new context. Already-consolidated earlier work stays retrievable;
existing pending source ranges remain explicit. Context pressure within a role
uses the existing exact recovery path and preserves source identity, current
corrective feedback, protected tool pairing and cancellation.

Detailed notes use linked ledger records; individual record framing does not
limit aggregate research. Checkpoints retain the next work and exact open record
IDs. Targeted `recordIds` retrieval reloads those notes through opaque cursors
bound to the exact query and ledger version. A changed filter or stale cursor
cannot silently skip work. Full result pagination remains necessary for export.

Under provider context pressure, the graph retains canonical messages and makes
a separate provider projection around an accepted checkpoint. It preserves
complete tool-call/result pairs, the task instructions and recoverable pending
work. Older finalized pages retain full findings and dismissals for synthesis;
when those exceed the configured provider budget, an explicit ID index enables
targeted retrieval. The final appendix still contains the complete accepted log.
There is no audit-specific time or file quota.

Provider progress includes nonvisible reasoning deltas after SDK conversion.
The OpenRouter adapter preserves its reasoning fields; the attempt watchdog
observes them without publishing reasoning text. Active reasoning can outlast
the first-progress interval. Empty metadata and stale attempts do not extend an
idle connection, and explicit caller deadlines and cancellation still apply.
Timeout diagnostics distinguish first progress, idle and absolute deadlines.

File search and directory discovery return continuation cursors, result versions
and scope exclusions. The model must recover unfinished pages of its queries;
narrowing a query does not discharge its predecessor. Requested byte/line windows
also remain recoverable. Context projection cannot erase those obligations.
See [the limit review](./security-research-limits.md) for the authority and recovery
behind retained transport and record bounds.

Durable evidence and counterevidence references have no count ceiling. Citation
requests retain the existing per-call batch size; add further citations through
successive updates using each accepted revision and omit `entry.evidenceRefs`
to retain earlier links. Explicit reference arrays still replace that array.
Replaying a write returns its original citation batch alongside the current
record, while targeted reads and final export preserve all accumulated links.
An invalid merged record returns safe field-level repair guidance without
writing a partial record.

## Malformed provider calls

Providers can return `invalid_tool_calls` separately from valid calls. Before
projection and approval, the graph pairs each invalid call with a non-executing
repair error. Valid siblings still pass through normal authorization and run
once. Rejected IDs cannot execute the placeholder arguments used to make the
provider history well formed. The next model turn can submit corrected JSON.
Repeated invalid-only calls use the canonical no-progress policy. A delivered
security error remains a failed tool result, and successful status polling
cannot reset repeated failures of the results/finalization operation. When that
guard ends a run, the tools node first commits its protected final receipt through
the ordinary checkpoint/transcript path. The next pre-model node raises the same
typed stop before invoking a model. Fresh requests reset their failure episode;
approval resumes retain it. No raw receipt is attached to generic errors or logs.

## Source cards and observability

Security receipts cross a dedicated display projection before generic preview
bounds. The complete receipt is validated first, accepted note text stays whole,
and reference/index arrays become disclosed counts with saved-research recovery.
This display shape carries no cursor or report-readiness authority; canonical
receipts remain unchanged. Live and historical cards share this boundary.

Task transcripts share the ordinary tool-card renderer. File read/write cards
use read-only CodeMirror, select highlighting by path, and retain all received
source in the scrollable editor. Text-window envelopes render their content
with source line offsets and explicit partial-line/continuation labels. There
is no additional preview-line cutoff. Transport truncation remains disclosed;
CodeMirror cannot reconstruct bytes the transport did not deliver.

Security cards show aggregate file assignment, completed/pending review units,
excluded/unavailable entries, checkpoint next work and omitted projection counts,
with full received receipts available in details. Live Task activity keeps the
last meaningful operation and accepted note while model waiting/responding is
secondary. Inventory traversal reports observed files/directories during startup.
Reconnect and approval resume preserve durable activity/counts without persisting
private source text in shared Task metadata. Relay dispatch bypasses native tool
tracing, so Task progress observes accepted results on the canonical tools-node
event path as well. A receipt wait is not labelled model
work. Status is evidence of activity, not a claim about the quality of reasoning.
Successful normalized file operations also carry a content-free operation label
from the invocation service. That label restores concrete progress after a
repaired provider call; arbitrary file contents cannot impersonate the label.

## Compatibility

Deploy the matching server/agent and Desktop build to use the new finalization
contract. A new agent rejects a legacy Desktop receipt that cannot demonstrate
accountable inventory with an explicit upgrade error. Existing ledgers remain
readable; old reviewed labels are not retroactive inventory proof. Older Desktop
builds may reject ledgers after new fields have been written, so preserve the
updated Desktop when continuing those investigations. No database migration or
new permission grant is introduced.
Earlier reports are historical results, not retroactive qualification.


## Model context recovery

Reaching a model's input window does not require starting a replacement audit.
The runtime retains the canonical transcript and evidence ledger, projects bulky
receipts out of the working request, and enters an explicit recovery phase.
The same selected model reads exact historical pages, saves material notes,
and checkpoints before continuing the same Task and scan. Ordinary continuation
uses `continueContext:true`; the runtime carries the exact pending selection and
byte cursor. Explicit references and ranges remain available for chosen lookups.
Presented substantive pages stay in the working context through tool corrections
until consolidation. The runtime requests a checkpoint when actual workspace
pressure requires one or the recovery batch is complete, rather than after every
page. New investigation and finalization are blocked while required input remains
unconsolidated.
Saved-note acknowledgements remain reloadable ledger state rather than becoming
new mandatory source reads. Their compact receipts retain record identity and
citation provenance. Recovery guard corrections appear as actionable tool-card
errors; a repeated blocked request is distinguished from intervening verified
historical byte progress.

A frozen saved-record index remains available after checkpoint windowing, even
when the latest checkpoint lists no open record IDs. The model can find earlier
notes by record kind or exact declared/cited source path, then retrieve the full
latest record or its exact historical receipt. Checkpoints are cumulative
handoffs of the investigation plan; a checkpoint about one recovered page must
not turn previously investigated files into unread work. Index metadata is not
source evidence. Both historical-message and saved-record indexes are optional
navigation: neither creates mandatory recovery debt, advances recovered input
bytes, nor requires a semantic checkpoint. The model can consult them to find
useful prior work without consuming the entire index.

Only verified exact copies of previously accepted notes or inventory pages can
leave the mandatory source queue as saved-state echoes. First copies, changed
input and unknown status prose remain recoverable work. Status projections keep
current coverage states and scanner limitations; compact prompt controls use
the latest accepted progress receipt and identify the older status snapshot
separately. None of these projections establishes the correctness of saved
analysis or complete source coverage.

The context reader is server-local and restricted to the active authorized
research TaskRun. Its references bind the owner, Task, Run and immutable visible
message bytes and the originating file request. Recovered file pages carry the
verified path, zone and command even when the original request has left the
working window. Unknown source identity is explicit; the model must not guess
a citation path. Historical file entries distinguish successful, failed and
unknown original outcomes. An attempted path does not establish a successful
read, and successful delivery does not establish semantic inspection. It does not rerun searches, reread changed files, grant access
to another task, expose hidden reasoning, or create new source citations.
Progress distinguishes recovery and historical byte ranges from source-review
coverage. Cards show runtime recovery facts separately from model-authored
checkpoint notes; a claim in a note cannot clear pending runtime input. Byte
counts describe recovered historical input, which can include source output and
unsaved reasoning, and are not code-coverage counts. Finalized-report recovery reads the already accepted immutable notes
and continues synthesis without reopening the scan.

Both proactive budgeting and provider context rejection use this path. Tool
schemas count toward input, fresh pages receive workspace, and retries must
strictly reduce input on the same model. This does not promise that arbitrary
system instructions fit every model or certify the completeness of an audit;
coverage, quality, exclusions and full report delivery remain separate checks.


## Parent Task inspection

A parent Genie cannot infer audit quality from an errored lifecycle state or a
shortened transcript. Small `task.read` responses retain the complete existing
shape when it fits the caller's response allowance. Larger responses return
lifecycle facts and explicit selectors for metadata, a chosen run's result, and
its transcript. The full task prompt and all run descriptors remain retrievable
through metadata. No beginning/end excerpt replaces missing middle content.

Selected sections use exact UTF-8 byte pages with a frozen source version and
server-managed `continueRead:true` continuation. Transcript snapshots bind the
selected run and last included database row, so later appends do not change
earlier pages. Every continuation rechecks the existing owner, task, run and
visible-transcript authority. Literal transcript search locates matching entries;
its results are neither the full transcript nor evidence of semantic inspection.

If a smaller model window omits a previously returned page, the prepared input
contains its exact original replay selection and the runtime records that the
page was not presented. Continuation covers the first unread gap. The retained
canonical receipt remains intact; a projected receipt cannot claim that its
missing contents reached the model. Parent explanations must distinguish what
they retrieved from what the worker or its checkpoint merely claimed.
